# API design (REST Route Handlers)

Serves: BE-4, BE-5, BE-7, DISC-2, DISC-3, DISC-4, REG-2, REG-3, REG-5, ORG-1, ORG-2, ORG-3, ORG-4, DEL-1.
Related: `backend-architecture`, `zod-validation`, `backend-security`, `api-integration` (client side), `documentation-deliverables`.

## Purpose
A consistent, predictable HTTP contract that the client can parse with the same Zod schemas the server validates with.

## MUST
- Every route is built with the `route()` wrapper (`src/core/http/route-handler.ts`). In Next 16, `params` is a Promise; type the context with the global `RouteContext<"/api/events/[eventId]">` helper (generated by `next dev/build/typegen`; verify in `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/route.md`).
- Template (order matters):
  1. **Authenticate/authorize** (`auth: "PUBLIC" | "USER" | "ORGANIZER"` option; ownership is checked in the service with the `actor`).
  2. **Parse** `await params`, `searchParams` (from `req.nextUrl`), JSON body with Zod `safeParse` → `ValidationError` on failure (never trust types).
  3. **Call exactly one service method.**
  4. **Parse the result with the Zod response schema** (guards against leaking fields) and return the envelope.
- Envelope: `{ data }` or `{ data, meta: { page, pageSize, total } }`; errors `{ error: { code, message, details? } }`. `Content-Type: application/json`. Include `x-request-id` header.
- Status codes: `200` read/update, `201` create (+ `Location`), `204` delete with no body (or `200 { data }` if the client needs the entity), `400` validation, `401` not signed in, `403` signed in but not allowed, `404` not found **or not yours** (don't reveal existence), `409` conflicts (`EVENT_FULL`, `ALREADY_REGISTERED`, `POLL_CLOSED`), `422` not used, `429` rate-limited, `500` generic.
- Resources are plural nouns, ids as `[eventId]`, `[sessionId]`; verbs only for true actions (`/me/password`, `/me/notifications/read`).
- Query conventions (events list, DISC-2..4): `q` (name search), `category`, `type` (`in_person|online|hybrid`), `price` (`free|paid`), `from`, `to` (ISO dates), `sort` (`date|popularity|price`), `order` (`asc|desc`), `page` (≥1, default 1), `pageSize` (1..50, default 12). Unknown params are ignored; invalid → 400. Sorting/filtering whitelisted in the service, never interpolated.
- Idempotency: webhooks dedupe on the provider event id (`stripe_events`); client retries of `POST` that create paid checkouts use an idempotency key (Stripe `idempotencyKey`); `PUT/DELETE` are naturally idempotent.
- Mutation responses return the updated resource DTO so RTK Query can update its cache.
- Keep `docs/api/` collection (Postman/Bruno) in sync whenever a route or schema changes (`/api-collection`).

## MUST NOT
- No business logic, SQL or Drizzle in route files; no raw rows returned; no stack traces or SQL errors in responses.
- No `export const dynamic`/`revalidate` style segment config unless the docs confirm it is allowed with `cacheComponents` (it generally is not); route handlers are request-time by default here.
- No 200 responses for errors; no different error shapes per route.
- No ownership decided by a client-supplied `userId` (use the session actor; `/api/me/*` never takes a user id).

## Example: events list (DISC-2..4)
```ts
// src/app/api/events/route.ts
export const GET = route({ auth: "PUBLIC" }, async ({ req }) => {
  const query = eventListQuerySchema.parse(Object.fromEntries(req.nextUrl.searchParams));
  const { items, total } = await eventsService.list(query);
  return ok(eventListResponseSchema.parse({ data: items, meta: { page: query.page, pageSize: query.pageSize, total } }));
});
```
`eventListQuerySchema` coerces (`z.coerce.number()`), defaults, and whitelists `sort`; the same schema is used by the client to build the URL (`api-integration`).

## Common mistakes
- Returning `404` vs `403` inconsistently for other people's resources (use 404 for "not yours").
- Parsing the body with `req.json()` without catching invalid JSON → 500 instead of 400.
- Forgetting `await params` in this Next version.
- Different pagination shapes across endpoints; unbounded `pageSize`.
- Updating the Zod schema but not the API collection.

## Final checklist
- [ ] Wrapper used; guard first; params/query/body parsed; one service call; response parsed.
- [ ] Correct status codes and domain errors; envelope shape consistent.
- [ ] No ownership from client input; no sensitive fields.
- [ ] Rate limit on auth/vote/reset routes (`backend-security`).
- [ ] Integration test for the route; API collection updated.
